# Add a diagnostic code

Goal: give a new condition a stable `VAR-` code, generate its documentation
page, and make the tool report it without breaking any consumer.

The rules live in [ADR 0002: diagnostic codes](../adr/0002-diagnostic-codes.md).
Read it, and [CONVENTIONS.md](../../CONVENTIONS.md) (mandatory for every
contributor), before you start.

This guide serves the open issues
[#15](https://github.com/HarnageaGabriel/varco/issues/15)
(`probe: report the TLS versions an endpoint accepts`, which asks for a new
`VAR-CMP-*` code) and
[#16](https://github.com/HarnageaGabriel/varco/issues/16)
(`probe: detect HTTP/2 (ALPN) differences`, which adds a new compared field).
The other guides are in the [dev guide index](README.md).

## The registry

The registry is [internal/diag/diag.go](../../internal/diag/diag.go). It is the
single source of truth: the code constant, the entry that describes it, and the
generated documentation all come from there.

The code is a named string type:

```go
// Code is a stable diagnostic identifier.
type Code string
```

Every code has a constant in one `const` block, with a doc comment:

```go
	// CodePlanConfigMap reports a controller ConfigMap setting that can change
	// observable request or response behavior.
	CodePlanConfigMap Code = "VAR-PLAN-0010"
```

The registry itself is a slice literal inside `List()`, sorted by code:

```go
// List returns registry entries sorted by code.
func List() []Entry {
	entries := []Entry{
		{Code: CodeCompareStatus, Area: "CMP", Title: "Status differs", Severity: SeverityInfo, Description: "The endpoints returned different HTTP status codes.", Remediation: "Confirm that routing and application behavior are equivalent."},
		...
	}
	sort.Slice(entries, func(i, j int) bool { return entries[i].Code < entries[j].Code })
	return entries
}
```

An `Entry` carries the whole description of the code:

```go
// Entry describes one registered diagnostic code.
type Entry struct {
	Code        Code
	Area        string
	Title       string
	Severity    Severity
	Description string
	Remediation string
}
```

`Severity` has three values: `SeverityError`, `SeverityWarning` and
`SeverityInfo`. A severity is a property of the code, never of the call site.

Three functions make up the API:

| Function | Behaviour |
|---|---|
| `List() []Entry` | every registered entry, sorted by code |
| `Lookup(code Code) (Entry, bool)` | the entry for a code; `(Entry{}, false)` when the code is unknown |
| `New(code Code, message string) (Diagnostic, error)` | a `Diagnostic` with the registry severity; an empty message falls back to `entry.Title` |

`New` refuses an unregistered code:

```go
func New(code Code, message string) (Diagnostic, error) {
	entry, ok := Lookup(code)
	if !ok {
		return Diagnostic{}, fmt.Errorf("unknown diagnostic code %q", code)
	}
	...
}
```

`Lookup` is a linear scan over `List()`, so registering a code is the only
thing needed to make it findable.

## Codes and areas

ADR 0002 fixes the shape of a code:

> Every diagnostic uses `VAR-<AREA>-NNNN`, where the area is one of `CFG`,
> `PLAN`, `RUN`, `NET`, `TLS`, `CMP`, or `RPT`. Codes are never reassigned to a
> different meaning.

The areas in use today, with the next free number in each:

| Area | Meaning | Codes today | Next free |
|---|---|---|---|
| `CFG` | configuration and flags | `VAR-CFG-0001`, `VAR-CFG-0002` | `VAR-CFG-0003` |
| `NET` | connectivity | `VAR-NET-0001` | `VAR-NET-0002` |
| `RUN` | run and policy | `VAR-RUN-0001` | `VAR-RUN-0002` |
| `CMP` | comparison results | `VAR-CMP-0001` .. `VAR-CMP-0007` | `VAR-CMP-0008` |
| `PLAN` | planning | `VAR-PLAN-0001` .. `VAR-PLAN-0011` | `VAR-PLAN-0012` |
| `TLS` | reserved, no code yet | - | `VAR-TLS-0001` |
| `RPT` | reserved, no code yet | - | `VAR-RPT-0001` |

Take the next free number in the area that matches the condition. **Never
reassign an existing code to a different meaning** and never reuse a number
that was retired: automation keys on the code.

## The generated documentation

The pages under [docs/diagnostics](../diagnostics/) are generated by
[tools/docsgen](../../tools/docsgen). There is one page per code plus the
index [docs/diagnostics/README.md](../diagnostics/README.md). Every page starts
with the marker

```
<!-- Code generated by tools/docsgen; DO NOT EDIT. -->
```

**Never hand-write a page in that directory.** `docsgen` removes any `*.md`
file in the output directory that the registry does not produce, so a
hand-written page is deleted by `make docs` and reported as stale by
`make docs-check`.

The generator has two flags:

| Flag | Meaning |
|---|---|
| `-out DIR` | the output directory, default `docs/diagnostics` |
| `-check` | compare the files on disk with the generated pages and report drift; writes nothing |

The page template is `renderPage` in
[tools/docsgen/main.go](../../tools/docsgen/main.go):

```
<!-- Code generated by tools/docsgen; DO NOT EDIT. -->

# VAR-PLAN-0010: Controller ConfigMap setting

- Severity: warning
- Area: PLAN

## Description

An ingress-nginx controller ConfigMap setting can change observable request or response behavior and is not encoded in an Ingress manifest.

## Remediation

Compare the value on both controllers and verify the behavior against the ingress-nginx ConfigMap documentation.
```

The index is generated too, one row per code. The link target is relative to
`docs/diagnostics/`, the directory the index lives in:

```
| [VAR-PLAN-0010](VAR-PLAN-0010.md) | warning | Controller ConfigMap setting |
```

## Files to touch

| File | What changes |
|---|---|
| [internal/diag/diag.go](../../internal/diag/diag.go) | the `Code` constant and the `Entry` in `List()` |
| the place that raises the diagnostic | a `plan.Finding`, a `plan.Warning`, a `compare.Difference` or a `diag.New` call |
| [docs/diagnostics/](../diagnostics/) | **generated**, never edited by hand |
| [docs/plan.md](../plan.md), [docs/run.md](../run.md), [docs/troubleshooting.md](../troubleshooting.md) | the hand-written tables and the user-visible symptom, when the code is user-visible |
| [internal/diag/diag_test.go](../../internal/diag/diag_test.go) | the registry test |

## Worked example: `VAR-PLAN-0010`

`VAR-PLAN-0010` is the controller ConfigMap warning. It shows the whole
pattern: a constant, an entry, a raise site, a generated page and a test.

**1. The constant** in [internal/diag/diag.go](../../internal/diag/diag.go):

```go
	// CodePlanConfigMap reports a controller ConfigMap setting that can change
	// observable request or response behavior.
	CodePlanConfigMap Code = "VAR-PLAN-0010"
```

**2. The entry** in `List()`, same file:

```go
{Code: CodePlanConfigMap, Area: "PLAN", Title: "Controller ConfigMap setting", Severity: SeverityWarning, Description: "An ingress-nginx controller ConfigMap setting can change observable request or response behavior and is not encoded in an Ingress manifest.", Remediation: "Compare the value on both controllers and verify the behavior against the ingress-nginx ConfigMap documentation."},
```

**3. The raise site.** A planning warning is a `plan.Warning` with the code
([internal/plan/configmap.go](../../internal/plan/configmap.go)):

```go
// ConfigMapWarnings reports ingress-nginx ConfigMap settings that are visible
// on the wire. The fixed table keeps output deterministic and ignores unknown
// keys. Source: https://kubernetes.github.io/ingress-nginx/user-guide/nginx-configuration/configmap/
func ConfigMapWarnings(config map[string]string) []Warning {
```

A runtime failure is a `*diag.Error`; `internal/probe/probe.go` has
`diagnosticError(code diag.Code, message string, cause error) error` for that,
and `internal/policy/policy.go` builds one directly.

**4. The generated page**
[docs/diagnostics/VAR-PLAN-0010.md](../diagnostics/VAR-PLAN-0010.md) and its
row in the index.

**5. The test.** [internal/diag/diag_test.go](../../internal/diag/diag_test.go)
has `TestRegistry`, which looks codes up and asserts the severity, and
`TestNew`, which covers the default message, a custom message and an unknown
code.

## Where a diagnostic surfaces

| Surface | Where |
|---|---|
| stderr | `diagFailure` in [internal/cli/cli.go](../../internal/cli/cli.go) prints `<CODE>: <message>` |
| plan JSON | `plan.Finding` and `plan.Warning` carry the code in the `code` field |
| plan table | `PlanTable` in [internal/report/plan.go](../../internal/report/plan.go) prints a `CODE` column under `UNSUPPORTED` and `WARNINGS` |
| run JSON | `model.Difference.Code` and `model.Evaluation.Error` |
| run table | the `CODE` column of the case table in [internal/report/run.go](../../internal/report/run.go) |

An unregistered code is an internal error, not a warning. `diagFailure` prints
the bare message without the `VAR-` prefix and returns exit code 4, which
[internal/cli/cli_edges_test.go](../../internal/cli/cli_edges_test.go) asserts.

## Tests and commands

| What | Command |
|---|---|
| regenerate the pages | `make docs` (or `go run ./tools/docsgen -out docs/diagnostics`) |
| check for drift | `make docs-check` (or `go run ./tools/docsgen -out docs/diagnostics -check`) |
| the generator's own tests | `go test ./tools/docsgen` |
| the registry tests | `go test ./internal/diag` |
| the whole tree | `go test ./...` |
| the lint gate | `golangci-lint run ./...` |

CI runs `make docs-check` in the `Supply-chain checks` job, so a code that was
registered but not regenerated fails the pull request with

```
generated docs out of date (run `make docs`): VAR-PLAN-0012.md
```

After `make docs`, read the diff. The generated page must match the
`Description` and `Remediation` you wrote, and the index must have exactly one
new row.

## Checklist

- [ ] You read [ADR 0002](../adr/0002-diagnostic-codes.md).
- [ ] The area matches the condition (`CFG`, `PLAN`, `RUN`, `NET`, `TLS`,
      `CMP` or `RPT`).
- [ ] The number is the next free one in that area, and no existing code
      changed meaning.
- [ ] The constant has a doc comment, and the `Entry` has an `Area`, a
      `Title`, a `Severity`, a `Description` and a `Remediation`.
- [ ] The severity is `error`, `warning` or `info`, and it is the severity of
      the condition, not of the call site.
- [ ] The code is raised through `diag.New`, or as the `Code` of a
      `plan.Finding`, a `plan.Warning` or a `compare.Difference`.
- [ ] `make docs` was run and the generated page and index were reviewed.
- [ ] `make docs-check` passes.
- [ ] The hand-written docs that mention the condition (the plan findings and
      warnings tables, the troubleshooting guide) were updated.
- [ ] `go test ./...` passes and `golangci-lint run ./...` is clean.
- [ ] The commit is signed off (`git commit -s`).
